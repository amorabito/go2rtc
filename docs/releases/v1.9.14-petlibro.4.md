# PLAF203 Native Transport Protocol Corrections

Promotes the hardware-tested `v1.9.14-petlibro.4-dev.2` implementation to the
normal Petlibro release stream. The transport implementation is unchanged from
that candidate; this release also includes standalone documentation cleanup.

## Changes

- Track validated transport receipt independently of H.264/AAC decoding so
  unusable media does not create false ACK holes.
- Correlate native receive-reset requests and completions, accept the observed
  device protocol version, and use the correct initial reliable sequence.
- Preserve actual sequence and receipt tracking across bootstrap and runtime.
- Implement applicable sender-clear and receiver-reset operations independently
  of reliable-control acknowledgement.
- Correct normal/timed packet validation, retransmissions, 16-bit fragment
  counts, and fragmented AAC assembly.
- Align ACK scheduling with the native 100 ms gate and prompt reliable-control
  progress. Remove capture-specific startup assumptions without adding modes.
- Retain the Petlibro app requirement for initial Wi-Fi onboarding and correct
  standalone documentation links and license guidance.

These changes address defects that can contribute to persistent ACK gaps,
retransmission problems, and streaming degradation. They do not acknowledge
genuinely missing packets or introduce stale-hole abandonment, and do not prove
that every reported stream stall has the same cause. `quality=hd` remains a
startup-readiness preference, not a per-viewer encoder-resolution command.

Automated regression tests, race detection, static analysis, and Linux
cross-builds passed. Development candidates have completed user hardware
qualification, including the documented five-minute 1080p H.264/AAC decode run.
This publication does not install or activate anything on a physical device.

Linux AMD64, ARM64, and ARMv7 executables and archives are provided below.
Archives include `go2rtc`, `petlibro-resolve`, and both MIT license notices.
